30 Ansible Interview Questions

Core concepts, commands and playbook basics, with short answers.

1. What is Ansible?

Ansible is an open-source automation tool for configuration management, application deployment and orchestration. It is agentless and uses YAML playbooks to describe the desired state of systems.

2. Why is Ansible called agentless?

Nothing needs to be installed on managed nodes. Ansible connects over SSH (Linux) or WinRM (Windows) and runs modules temporarily, then removes them.

3. What are the main components of Ansible?
  • Control node: where Ansible runs
  • Managed nodes: target hosts
  • Inventory: list of hosts
  • Modules: units of work
  • Playbooks: YAML automation files
  • Roles, plugins, variables, facts
4. What is an inventory file?

A file listing the hosts and groups Ansible manages. It can be INI or YAML and static or dynamic. Default path: /etc/ansible/hosts.

[web]
web1.example.com
web2.example.com

[db]
db1.example.com ansible_user=admin
5. What is a playbook?

A YAML file containing one or more plays. Each play maps a group of hosts to a list of tasks.

---
- name: Install nginx
  hosts: web
  become: yes
  tasks:
    - name: Install package
      ansible.builtin.apt:
        name: nginx
        state: present
6. What is a module in Ansible?

A module is a small program that performs a specific task, such as apt, copy, service or user. Tasks call modules with arguments.

7. What is the difference between a task and a play?

A task is a single call to a module. A play is a set of tasks applied to a group of hosts. A playbook contains one or more plays.

8. What is idempotency?

Running the same playbook repeatedly gives the same result without unwanted changes. If the system is already in the desired state, Ansible reports ok instead of changed.

9. What is the difference between ad-hoc commands and playbooks?

Ad-hoc commands are one-line tasks for quick jobs; playbooks are reusable, version-controlled files for repeatable automation.

ansible all -m ping
ansible web -m service -a "name=nginx state=restarted" -b
10. What is become in Ansible?

It enables privilege escalation (like sudo). Use become: yes at play or task level, and become_user to pick the target user.

11. What are handlers?

Handlers are tasks that run only when notified by another task that reported a change. They run once at the end of the play, commonly used to restart services.

tasks:
  - name: Update config
    ansible.builtin.template:
      src: nginx.conf.j2
      dest: /etc/nginx/nginx.conf
    notify: Restart nginx
handlers:
  - name: Restart nginx
    ansible.builtin.service:
      name: nginx
      state: restarted
12. What are variables and how are they defined?

Variables store values for reuse. They can be defined in playbooks (vars), inventory, group_vars, host_vars, external files (vars_files), or on the command line with -e.

13. What is variable precedence?

When a variable is defined in several places, the higher-priority one wins. Roughly, from low to high: role defaults, inventory vars, group_vars, host_vars, play vars, task vars, and finally extra vars (-e), which always win.

14. What are facts?

Facts are system details (OS, IP, memory, CPU) gathered automatically by the setup module at the start of a play. Access them like ansible_facts['os_family']. Disable with gather_facts: no.

15. What is a role?

A role is a standard directory structure for organizing tasks, handlers, templates, files, variables and defaults so automation can be reused and shared.

ansible-galaxy init myrole
myrole/
  tasks/ handlers/ templates/
  files/ vars/ defaults/ meta/
16. What is Ansible Galaxy?

A hub for sharing roles and collections. Install with ansible-galaxy install username.rolename or ansible-galaxy collection install namespace.name.

17. What is a template and which language does it use?

Templates are files (usually .j2) that use Jinja2 to insert variables and logic into config files, rendered by the template module.

server_name {{ server_name }};
listen {{ http_port | default(80) }};
18. What is the difference between copy and template modules?

copy transfers a file as-is. template processes a Jinja2 file with variables before transferring it.

19. How do loops work in Ansible?

Use the loop keyword (older: with_items) and reference each item with {{ item }}.

- name: Install packages
  ansible.builtin.apt:
    name: "{{ item }}"
    state: present
  loop: [git, curl, vim]
20. How do you use conditionals?

Use the when keyword with a Jinja2 expression (no braces needed).

- name: Install Apache on Debian
  ansible.builtin.apt:
    name: apache2
  when: ansible_facts['os_family'] == "Debian"
21. What is Ansible Vault?

A feature to encrypt sensitive data such as passwords and keys.

ansible-vault create secrets.yml
ansible-vault edit secrets.yml
ansible-vault encrypt / decrypt file.yml
ansible-playbook site.yml --ask-vault-pass
22. What is the difference between command, shell and raw modules?
  • command: runs a command without a shell (no pipes or redirects); default and safest
  • shell: runs through /bin/sh, so pipes and variables work
  • raw: sends a raw SSH command; needs no Python on the target
23. How do you check a playbook before running it?
ansible-playbook site.yml --syntax-check
ansible-playbook site.yml --check          # dry run
ansible-playbook site.yml --check --diff   # show changes
ansible-lint site.yml
24. What are tags?

Tags label tasks so you can run or skip parts of a playbook.

ansible-playbook site.yml --tags "install"
ansible-playbook site.yml --skip-tags "config"
25. What does register do?

It stores a task's result in a variable for later use, such as in conditionals or debug output.

- ansible.builtin.command: whoami
  register: result
- ansible.builtin.debug:
    var: result.stdout
26. How do you handle errors in a playbook?
  • ignore_errors: yes continues after a failure
  • failed_when defines custom failure conditions
  • block / rescue / always works like try/catch/finally
27. What is the difference between include_tasks and import_tasks?

import_tasks is static: processed when the playbook is parsed. include_tasks is dynamic: processed at runtime, so it works with loops and runtime variables.

28. What is the purpose of ansible.cfg?

It holds default settings such as inventory path, remote user, forks and privilege escalation. Ansible reads the first found of: ANSIBLE_CONFIG variable, ./ansible.cfg, ~/.ansible.cfg, /etc/ansible/ansible.cfg.

29. What are dynamic inventories?

Inventories generated at runtime from a source such as AWS, Azure or GCP using inventory plugins or scripts, so host lists stay current without manual edits.

30. What is the difference between Ansible and Puppet/Chef?
  • Ansible is agentless (SSH); Puppet and Chef usually need agents
  • Ansible uses YAML; Puppet uses its own DSL and Chef uses Ruby
  • Ansible is push-based by default; Puppet and Chef are pull-based
  • Ansible has a lower learning curve
